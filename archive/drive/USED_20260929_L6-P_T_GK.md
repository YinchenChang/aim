## 1. 落差陳述

同步訓練作業任一卡停則整份停。作業故障率 `λ_job ≈ N × λ_card`，故 `MTTF_job ≈ 1/(N λ)`。錯價只在把單卡可靠度或實例 SLA 讀成大 N 作業的有效時數。種子第二句 `∂ETTR/∂N < 0` 僅在 `T_recover` 不隨 N 同比下降時成立。測一已並列 N 與作業 MTTF；ETTR 在已觀測窗仍高。本卡不把 MTTF 下降寫成 ETTR 缺口已被定價。

## 3. 最強反方（具名）

**R2 為載重反方。** Epoch AI，*Hardware failures won’t limit AI scaling*，2024-11-22：對 Llama 快照反解約 50,000 GPU-h／中斷，結論近中期 checkpoint 不限制規模，該次損失約 2.1%。`[I]` 研究機構，有立場（規模可續）。與 Llama 3 原文 >90% 同向。MTTF∝1/N 不被此拒絕；「ETTR 隨 N 降且未被吸收」被此打成未證。R1 次之：CRWV 10-Q 同檔無計費 GPU-h × 有效訓練時數 `[V]` 測一。R6：Delta 投影 99.9% 作業可用率約需 5% 超配，缺口可內化成成本 `[V]` 論文，不進通過條件。

## 4. 競爭假說與 N_d

`N_d＝4`。與「可捕捉之 ETTR(N) 落差」競爭、且測一未殺死：

1. H_recover：`T_recover` 夠短，ETTR 不隨 N 單調降（R2；Llama >90%）。
2. H_line：申報層只有實例 SLA／營收，無作業 ETTR 科目（R1）。
3. H_spare：超配／熱備把缺口吃進成本、不進價（R6）。
4. H_cell：寫成 checkpoint 儲存、熱循環或空方＝換格（R5；本卡不選）。

H0 的 MTTF 句與 ETTR 句要拆開。MTTF 句在 1 成立時仍真。ETTR 可捕捉句要 1–3 同時不成立。現況：1 有同向證據，2 成立為表達缺失，3 未排除。

## 5. 先驗（外部參照；只給區間）

機制先驗（MTTF∝1/N）：外部參照＝Kokolis 原文「hardware reliability shrinks inversely proportional to the number of GPUs」＋串聯模型。對「同步作業 MTTF 隨 N 降」給 **0.75–0.90**。`[V]` 實測比 0.88，不是全 N 域。
捕捉先驗（ETTR 缺口未吸收且 ≥12 個月可從科目拒絕 SLA）：外部參照＝Llama 3 >90% `[V]` 與 Epoch 2.1% `[I]`，方向皆是吸收。只給 **0.10–0.30**。`[A]`。無 H1。
